# J.A.R.V.I.S. v0.2.0 Release + Productization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a separate evidence-gated v0.2.0 RC/final release path, generate exact-commit evidence, update public product surfaces from measured results, and publish final v0.2.0 only when every mandatory gate is proven.

**Architecture:** Keep all v0.1.0 tags/workflows immutable. Add a v0.2.0-specific evidence builder, promotion gate and direct release runner that validate an exact SHA/tag, consume fresh direct-gate/benchmark/browser/claim evidence, refuse promotion when a mandatory artifact is absent, and support prerelease RCs before final promotion. GitHub Actions are not release-validation authority.

**Tech Stack:** Python 3.12 stdlib, Node/Playwright test-only browser smoke, existing PowerShell packaging/governance, responsibility-scoped direct evidence reports, GitHub Releases.

**Spec:** `docs/superpowers/specs/2026-09-15-jarvis-v0.2.0-optimization-design.md`

## Preconditions

- Plans 1–4 merged, with Plan 4 carrying fresh PASS reports for every mandatory direct gate/platform.
- `main` has named contract/integration/recovery/provider/browser/benchmark/claim gates.
- Repository-scale benchmark and evidence manifest are stable.
- No final version claims have been published prematurely.

## Task 3 — Direct v0.2.0 Release Runner

**Files:**
- Create: `tooling/run_v020_release.py`
- Create: `tests/test_agentic_v020_release_runner.py`
- Do not modify: `.github/workflows/release.yml`
- Do not modify: `.github/workflows/publish-v0.1.0-tag.yml`

Interface:

```bash
python tooling/run_v020_release.py \
  --tag v0.2.0-rc.1 \
  --expected-sha <candidate_sha> \
  --channel rc \
  --reports-dir reports \
  --output-dir release-artifacts/v0.2.0
```

For final promotion use `--tag v0.2.0 --channel final`.

The runner must:
1. validate tag format (`v0.2.0-rc.N` for RC, `v0.2.0` for final);
2. verify the current checkout/declared candidate equals `expected_sha`;
3. require fresh direct evidence reports for the exact candidate SHA and required platforms;
4. reject GitHub Actions/workflow status as substitute evidence;
5. run/verify the final portable battery, doctor/self-test and claim/release-evidence commands where the current platform is responsible;
6. validate benchmark/browser/recovery/provider/portable reports produced by their dedicated runners rather than silently rerunning or synthesizing them;
7. run legacy packaging/evidence only on its supported Windows path;
8. build the canonical release evidence bundle;
9. run the promotion gate;
10. emit a machine-readable release decision but **never create, move or overwrite a Git tag/release when the decision is not PASS**.

Publishing is a separate explicit GitHub Releases action after the direct runner returns PASS for the exact candidate. The publisher must verify the candidate tag target before upload and must not force-update an existing release tag.

Commit: `feat: add evidence-gated direct v0.2.0 release runner`

## Task 6 — Release-Candidate Dry Run

Create a candidate branch/tag only after Plan 4 has fresh direct PASS evidence. Run the direct release runner against an RC tag such as `v0.2.0-rc.1` and exact expected SHA before publishing anything.

Validate:
- direct release runner returns PASS for the exact candidate;
- prerelease is marked prerelease;
- evidence artifacts downloadable and non-empty;
- evidence hashes match candidate files;
- public docs do not describe RC as final;
- immutable v0.1.0 tag still peels to `accc50d727ef3d39d3929c4e4dd107e129e7d1a3`.

If any gate fails, fix through a normal PR, create a new RC candidate and never rewrite an already-published immutable evidence claim.

## Task 7 — Final v0.2.0 Promotion

Final promotion is allowed only when:

```text
portable runtime matrix              PASS
contracts/integration                 PASS
restart/recovery/idempotency          PASS
deterministic provider                PASS
browser/HUD smoke                     PASS
repository-scale context benchmark    PASS
resource measurement semantics        PASS
claim audit                           PASS
exact-SHA release evidence            PASS
v0.1.0 immutable target               PASS
```

Run the direct release runner with tag `v0.2.0`, exact SHA and `channel=final`. Only after PASS may an explicit GitHub Releases action create the immutable final tag/release and upload the already-built evidence bundle. Never force-update the tag.

After publication, verify release/tag/assets through GitHub APIs and re-check the exact candidate evidence bundle. Only then update any “latest stable” wording.
