# J.A.R.V.I.S. v0.2.0 Operational HUD + Observability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Turn correlated runtime receipts into an append-only operational timeline and expose that state truthfully through the existing local server and JARVIS HUD.

**Architecture:** Add one observability projection layer over receipts produced by Plans 1–2. The ledger is derived/audit state, not execution authority. Extend `tooling/jarvis_server.py` with read-only runtime APIs and evolve the current vanilla HUD/design-system incrementally without replacing existing panel IDs or routes.

**Tech Stack:** Python 3.12 stdlib; vanilla HTML/CSS/JS; Node built-in test runner; canonical `design-system/`.

**Spec:** `docs/superpowers/specs/2026-09-15-jarvis-v0.2.0-optimization-design.md`

## Preconditions

- Plans 1 and 2 are merged and green.
- Receipt correlation identifiers are stable.
- Adaptive Governor/context/memory/routing paths emit structured receipts.

## Task 1 — Append-Only Receipt Ledger

**Files:**
- Create: `tests/test_agentic_v020_observability.py`
- Create: `tooling/agentic/observability.py`
- Modify: `tooling/agentic/config.py`
- Modify: `tooling/agentic/runtime.py`

Add `receipts_dir` under state and implement an append-only JSONL ledger with deterministic serialization and credential redaction.

Required API:

```python
class ReceiptLedger:
    def append(self, receipt: Mapping[str, Any]) -> None: ...
    def for_mission(self, mission_id: str) -> list[dict]: ...
    def for_task(self, mission_id: str, task_id: str) -> list[dict]: ...
    def for_attempt(self, attempt_id: str) -> list[dict]: ...
    def for_trace(self, trace_id: str) -> list[dict]: ...
```

RED tests:
- append order is preserved;
- malformed/cross-mission correlation is rejected;
- API keys/bearer tokens are not persisted;
- restart reloads the same receipt history;
- ledger failure must not mutate authoritative mission state.

Commit: `feat: persist correlated runtime receipts append-only`

## Task 2 — Mission Timeline Projection

**Files:**
- Create: `tests/test_agentic_v020_mission_timeline.py`
- Modify: `tooling/agentic/observability.py`

Implement a pure projection:

```python
@dataclass(frozen=True)
class MissionTimeline:
    mission_id: str
    events: tuple[TimelineEvent, ...]
    resource_summary: dict
    verification_summary: dict
    unknown_fields: tuple[str, ...]
```

Ordering uses receipt timestamps with stable receipt-id tie-break. Project only structured state: admission, context, decision, execution, effects/recovery, verification, memory and Governor action. Do not expose hidden reasoning.

No-data semantics:
- no attempts => count 0 but rates `None`/NO_DATA;
- no measured latency/cost/tokens => UNKNOWN, not 0;
- no verifications => verification rate UNKNOWN, not 100%.

Commit: `feat: project mission receipt timelines`
