# J.A.R.V.I.S. v0.2.0 CI + Benchmarks + Documentation Evidence Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make each release claim map to a focused CI gate or machine-readable artifact, add deterministic provider/recovery/browser evidence, expand context benchmarking to repository scale, and reconcile current documentation with what the runtime actually proves.

**Architecture:** Preserve the existing portable runtime matrix and legacy governance while introducing focused validation jobs. Keep runtime zero-dependency; any browser-test dependency is pinned and test-only. Documentation claims are checked by a deterministic evidence manifest instead of prose convention alone.

**Tech Stack:** GitHub Actions; Python 3.12 stdlib; Node built-in tests; test-only browser automation if required; PowerShell legacy suites.

**Spec:** `docs/superpowers/specs/2026-09-15-jarvis-v0.2.0-optimization-design.md`

## Preconditions

- Plans 1–3 merged and green.
- Runtime receipts, Governor and HUD observability paths are stable enough to validate end to end.

## Task 1 — Deterministic Provider Fixture

**Files:**

- Create: `tests/test_agentic_v020_deterministic_provider.py`
- Modify: `tooling/agentic/adapters/inference.py` only if a minimal reusable fixture hook is required.

Fixture must support deterministic cases:

```text
SUCCESS transport with provider-reported usage
TRANSIENT failure
POLICY failure
LOW_CONFIDENCE response
MALFORMED/oversized response
```

Tests prove:
- no network/API key;
- backend callback was actually invoked;
- transport success does not set verification success by itself;
- provider token usage is MEASURED only when reported;
- cost remains UNKNOWN unless fixture explicitly reports measured cost through the supported contract;
- policy failure is terminal;
- fallback remains bounded.

Command:

```bash

```
