# J.A.R.V.I.S. v0.2.0 Validation + Benchmarks + Documentation Evidence Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make each release claim map to a focused direct evidence gate or machine-readable artifact, add deterministic provider/recovery/browser evidence, expand context benchmarking to repository scale, and reconcile current documentation with what the runtime actually proves.

**Architecture:** Preserve portable runtime and legacy governance coverage while introducing focused direct validation gates. Keep runtime zero-dependency; the browser-test dependency is pinned and test-only. Documentation claims are checked by a deterministic evidence manifest instead of prose convention alone.

**Tech Stack:** Python 3.12 stdlib; Node built-in tests; pinned test-only Playwright/Chromium; PowerShell legacy suites; direct JSON evidence reports.

**Spec:** `docs/superpowers/specs/2026-09-15-jarvis-v0.2.0-optimization-design.md`

## Preconditions

- Plans 1–3 are merged; final phase acceptance depends on fresh direct validation rather than workflow status.
- Runtime receipts, Governor and HUD observability paths are stable enough to validate end to end.

**Current implementation status (2026-09-18):** Tasks 1–7 artifacts are present through this plan. Task 8 fresh direct execution remains the phase-completion gate; implementation presence is not PASS evidence.
